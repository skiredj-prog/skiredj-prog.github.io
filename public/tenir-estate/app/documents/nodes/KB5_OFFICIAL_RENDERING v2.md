## 2. Rendering temperament
KB5 inherits the seven KB3 temperament principles and applies them specifically to the R5 deep-tech estate.

### 2.1 Sharp
NSL grammar is not LLM inference. Graph ontology is not schema governance. WebSocket streaming is not live distributed consensus. KB5 does not smooth these layers into "the system" for elegance. Each is real and separate.

### 2.2 Comprehensive
The rendering covers the full R5 path: neuro-symbolic parsing and inference, graph persistence, live topology, cryptographic proof, governance integration, and the infrastructure dependencies that make R5 deployable or blocked.

### 2.3 Sober
KB5 reproduces the verified count from the actual test suite that can run in an isolated environment — 65 tests passing in R5 wired, with governance spine installed first — rather than claiming "implementation complete" in a way that sounds like production ready.

### 2.4 Humble
R5 design assumes Neo4j availability, deterministic NSL parsing, and multi-node Merkle consensus. None of these are trivial in live partner conditions. KB5 names what is current, prototype, or gated, not what is universally solved.

### 2.5 Powerful
KB5 is firm about one architectural boundary: the governance spine remains the adjudication heart of R5. The NSL, graph, VPS, and ledger layers make the system richer and faster. They do not replace or bypass the admissibility decision.

### 2.6 Anticipatory
Because the WebSocket-driven VPS surface is visually compelling, KB5 flags in advance the predictable failure mode: a viewer mistaking a live 3D visualization for a completed production topology. The rendering exists partly to pre-empt that exact misreading.

### 2.7 Suspended
Where the R5 README claims "Implementation Complete," KB5 names the specific infrastructure, calibration, and deployment thresholds that remain gated. It keeps open what is prototype rather than deciding the more flattering read.
