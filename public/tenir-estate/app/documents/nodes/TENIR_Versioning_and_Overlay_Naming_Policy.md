# TENIR Versioning / Overlay Naming Policy

## Rule 1 — Canonical namespace
Reserved for constitutional framework versions only.
Examples: TENIR 2.0, future TENIR 2.1.

## Rule 2 — Knowledge base namespace
Reserved for doctrinal rendering only.
Examples: KB1, KB2.

## Rule 3 — Profile / overlay namespace
Reserved for specialized doctrinal modules that do not replace the canon.
Examples:
- Agentic Governance Profile v1.0
- Metabolic Profile v1.0
- Rhizomatic Profile v1.0

## Rule 4 — Platform namespace
Reserved for implementation releases only.
Examples: K+4 RC, K+5.

## Rule 5 — Product namespace
Reserved for user-facing products.
Examples: Lens v2, Engine API v1, Governance Console v1.

## Hard prohibition
No overlay, module, profile, or product may imitate a canonical version line.

## Historical resolution
The informal label “v3” is deprecated as a canonical reference. Its valid content must be either:
- absorbed into TENIR 2.0 if general and constitutional, or
- renamed under a profile/overlay namespace if sectoral.
